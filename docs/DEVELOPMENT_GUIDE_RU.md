# Руководство разработчика Anthropophage

Это руководство описывает текущую ветку `feature/inventory-interaction` и рассчитано на разработчика, который только осваивает Godot и GDScript.

## 1. Что представляет собой проект

Anthropophage — 3D игра от первого лица на Godot 4.7.2. В проекте используются:

- Terrain3D 1.0.2 для ландшафта и его физических коллизий;
- GDScript для логики игрока, предметов и интерфейса;
- обычные Godot-сцены `.tscn`;
- ресурсы `.tres` для описаний типов предметов;
- реальные `RigidBody3D` для предметов, которые падают и сталкиваются.

Уже есть следующие системы:

- движение игрока, прыжок, спринт и выносливость;
- камера от первого лица, FOV и эффекты движения;
- сетка инвентаря с текущим размером `2×2`, который задаётся в `InventoryDataModel.grid_size`;
- предметы размером 1×1, 1×2 и 2×2;
- стаки предметов и уникальные UID экземпляров;
- перетаскивание предметов, поворот клавишей R и подсветка клеток;
- подбор через E и выбрасывание;
- предмет в руках;
- физический захват объектов группы `grabbable`;
- Terrain3D с данными регионов в `scenes/terrain_data/`.

Двери, контейнеры, сохранения игры и полноценная система использования предметов пока не являются отдельными готовыми подсистемами. Их можно добавлять поверх существующего взаимодействия через метод `interact`.

## 2. Структура проекта

### Главные папки

```text
scenes/                  Сцены игры
scenes/items/            Сцены физических предметов
scenes/terrain_data/     Региональные данные Terrain3D
scripts/                 Игровая логика
scripts/inventory/       Модель инвентаря и его интерфейс
resources/items/         Описания типов предметов
models/                  3D модели
textures/                Текстуры
addons/terrain_3d/       Сторонний Terrain3D 1.0.2
docs/                    Документация проекта
```

### Важные файлы

| Файл | Роль | Когда вызывается |
|---|---|---|
| `project.godot` | Настройки проекта и клавиши | Загружается Godot |
| `scenes/world.tscn` | Основная сцена мира | Запускается первой |
| `scenes/player.tscn` | Узлы игрока, HUD и контроллеры | Создаётся в мире |
| `scenes/terrain.tscn` | Terrain3D и его настройки | Создаётся в мире |
| `scripts/player.gd` | Движение и камера игрока | Каждый физический кадр |
| `scripts/inventory/inventory_data.gd` | Данные инвентаря | При изменении предметов |
| `scripts/inventory/inventory_ui.gd` | Окно инвентаря | При вводе и открытии UI |
| `scripts/item_catalog.gd` | Единый каталог описаний | Когда нужен `ItemDefinition` |
| `resources/items/item_definition.gd` | Тип ресурса предмета | При загрузке `.tres` |
| `scripts/world_item.gd` | Физический подбираемый предмет | При создании `WorldItem` |
| `scripts/player_interaction.gd` | RayCast-подбор, руки и выброс | Каждый физический кадр и E/F |
| `scripts/physics_grab.gd` | Физический захват | Пока зажата ЛКМ |
| `scripts/terrain_camera_setup.gd` | Единственная настройка камеры Terrain3D | При старте мира |

`scripts/world_setup.gd` больше не подключён к `world.tscn`. Стартовые предметы редактируются непосредственно в сцене.

Размер сетки сейчас не зашит в интерфейсе: `InventoryUI` получает его из `InventoryDataModel.grid_size`. В текущем коде значение по умолчанию равно `Vector2i(2, 2)`. Если вернуть рабочую сетку 8×6, меняйте значение в модели и проверяйте, что размер панели UI создаётся из этого свойства.

## Редактирование интерфейса инвентаря в Godot Editor

Статическая часть окна инвентаря теперь находится в отдельных сценах. Это позволяет менять оформление через Scene Tree и Inspector, не переписывая `inventory_ui.gd`.

### Главная сцена UI

Откройте:

```text
scenes/ui/inventory/InventoryUI.tscn
```

Её структура:

```text
InventoryUI (Control)
├── Overlay
└── Window (PanelContainer)
	└── MainContainer (MarginContainer)
		└── Content (VBoxContainer)
			├── Header (HBoxContainer)
			│   ├── Title
			│   └── CloseButton
			├── Subtitle
			├── InventoryGrid (Control)
			│   ├── Cells
			│   └── ItemsLayer
			└── HelpText
```

Эта сцена регистрируется через `scenes/ui/GameUI.tscn` в массиве `HUD/GameUI/UIManager.panel_scenes`.

### Что можно менять в InventoryUI.tscn

Узел `Window`:

- размер окна через `custom_minimum_size` и offsets якоря;
- фон через Theme Variation `InventoryWindow` в `MainUITheme.tres`;
- цвет, прозрачность, границы и скругления через Theme Editor.

Узел `Window/MainContainer`:

- отступы от краёв окна;
- расстояние между заголовком, сеткой и подсказкой.

Узел `Header`:

- расстояние между заголовком и кнопкой закрытия;
- выравнивание элементов;
- минимальный размер кнопки.

Узел `Title`:

- текст заголовка;
- размер шрифта;
- цвет текста;
- выравнивание.

Узел `Overlay`:

- цвет затемнения;
- прозрачность;
- размер затемнённой области.

Узел `HelpText`:

- текст инструкции;
- размер и цвет шрифта;
- перенос строк.

### Размер клеток и расстояние между ними

Размер клетки и промежуток между клетками сейчас задаются экспортируемыми свойствами узла `InventoryUI`:

```gdscript
@export var cell_size: float = 62.0
@export var cell_gap: float = 5.0
```

Откройте `scenes/ui/inventory/InventoryUI.tscn`, выберите корневой узел `InventoryUI` и измените эти значения в Inspector. Скрипт использует их одновременно для:

- размера `InventoryGrid`;
- положения клеток;
- размеров карточек;
- преобразования мыши в координаты сетки;
- подсветки и предпросмотра.

Не меняйте размер клеток вручную только у одной клетки в `InventoryCell.tscn`: положение и размер остальных клеток рассчитываются из `cell_size` и `cell_gap`.

### Внешний вид клетки

Откройте:

```text
scenes/ui/inventory/InventoryCell.tscn
```

Оформление находится в Theme Variation `InventoryCell` ресурса `resources/themes/MainUITheme.tres`. Можно менять:

- `bg_color`;
- `border_color`;
- толщину границ;
- радиус скругления.

В runtime скрипт создаёт клетки через эту PackedScene, поэтому изменение одной сцены применяется ко всей сетке.

Во время перетаскивания `inventory_ui.gd` временно меняет стиль клетки на зелёный или красный. Эти два состояния создаются кодом, потому что их цвет зависит от результата проверки `InventoryDataModel.can_place()`.

## Единая Theme и модульные панели UI

### Где находится общая Theme

Общий ресурс оформления находится здесь:

```text
resources/themes/MainUITheme.tres
```

Он назначен корню `scenes/ui/GameUI.tscn`. Все панели, созданные внутри `GameUI/UIManager`, получают этот ресурс через обычное наследование Godot. Поэтому цвет, шрифт и базовый стиль не нужно копировать в каждую сцену.

Чтобы изменить оформление, откройте `MainUITheme.tres` в Inspector и используйте Theme Editor. В ресурсе есть базовые типы `Panel`, `PanelContainer`, `Button`, `Label`, `LineEdit` и `ScrollContainer`, а также специальные Theme Variations:

- `InventoryWindow` — окно инвентаря;
- `InventoryCell` — клетка сетки;
- `InventoryItemCard` — карточка предмета;
- `InventoryCloseButton` — кнопка закрытия;
- `TestPanel` — демонстрационная панель.

Theme задаёт общий стиль для типа элемента. `theme_override_*` у отдельного узла имеет приоритет и перекрывает Theme, поэтому используйте локальные overrides только для особого элемента. `theme_type_variation` позволяет изменить стиль конкретной разновидности, не меняя все обычные кнопки и панели.

### Структура игрового UI

В `scenes/player.tscn` теперь находится один корневой UI-инстанс:

```text
Player
└── HUD (CanvasLayer)
    └── GameUI (scenes/ui/GameUI.tscn)
        └── UIManager
            ├── InventoryUI (создаётся из panel_scenes)
            └── TestPanel (создаётся из panel_scenes)
```

`GameUI` отвечает за общий Canvas и Theme. `UIManager` управляет только регистрацией, видимостью и переключением окон. Он не знает, что такое предмет, рецепт или физика. Каждая панель хранит собственную логику внутри своей сцены и скрипта.

Общий контракт находится в `scripts/ui/ui_panel.gd`. Он содержит `panel_id`, `open_action`, `display_mode`, `is_open` и методы `open_panel()`, `close_panel()`, `toggle_panel()`. Сигналы `panel_opened` и `panel_closed` позволяют менеджеру менять курсор, не вмешиваясь в содержимое панели.

`UIManager` находится в `scripts/ui/ui_manager.gd`. В его `panel_scenes` через Inspector добавляются PackedScene панелей. При запуске он создаёт экземпляры, проверяет наличие ID и уникальность ID, а затем хранит их в `registered_panels`.

Поток открытия инвентаря:

```text
Tab
 ↓
Input Map: open_inventory
 ↓
UIManager ищет панель с open_action = "open_inventory"
 ↓
InventoryUI.open_panel()
 ↓
InventoryUI обновляет карточки из InventoryDataModel
```

При открытии первой панели UIManager сохраняет текущий `Input.mouse_mode` и показывает курсор. Когда закрыта последняя панель, исходный режим возвращается. Поэтому overlay-панель не может случайно вернуть управление игроку, пока другое окно ещё открыто. `exclusive` закрывает другие exclusive-панели перед открытием; `overlay` может находиться поверх уже открытого окна.

### Как добавить новую панель через Editor

Например, для будущего окна крафта:

1. Создайте `scenes/ui/panels/CraftingPanel.tscn`.
2. Добавьте корневой `Control` и назначьте ему `scripts/ui/ui_panel.gd`.
3. В Inspector укажите `panel_id = "crafting"`, `open_action = "open_crafting"` и нужный `display_mode`.
4. Внутри сцены создайте свои `PanelContainer`, `Label`, `Button` и другие узлы. Их логика не должна попадать в `UIManager`.
5. При необходимости создайте `scripts/ui/crafting_panel.gd`, унаследуйте его от `UIPanel` и назначьте этот скрипт корню вместо базового.
6. Добавьте действие `open_crafting` в Project Settings → Input Map и назначьте клавишу.
7. Откройте `scenes/ui/GameUI.tscn`, выберите `UIManager` и добавьте `CraftingPanel.tscn` в массив `Panel Scenes`.
8. Убедитесь, что `panel_id` уникален и что корень новой сцены действительно является `UIPanel`.
9. Для общего оформления назначьте Theme `MainUITheme.tres` корню GameUI. Для отдельного вида добавьте Theme Variation в Theme Editor и укажите `theme_type_variation` у нужного узла.

После этого `UIManager` зарегистрирует окно без изменения `inventory_ui.gd` и без добавления условий в `ui_manager.gd`. Если крафту нужны рецепты, он получает их через собственную игровую систему или ресурс рецептов.

### Клавиши открытия панелей

Клавиши открытия задаются только в `project.godot`, а `UIManager` использует имена действий из `open_action`:

```text
open_inventory  → Tab
open_test_panel → F7
```

Проверять нужно именно имя действия и его событие в Project Settings → Input Map. Наличие строки `open_inventory` ещё не означает, что она привязана к Tab. Если в `InputEventKey` указан неправильный `keycode`, действие существует, но нажатие нужной клавиши его не вызовет. Быстрая диагностика: временно выведите `InputMap.action_get_events(&"open_inventory")` и сравните результат с Tab; аналогично проверьте `open_test_panel` и F7.

Все клавиши открытия проходят через один `UIManager._unhandled_input()`. Не добавляйте отдельный обработчик Tab в `InventoryUI` или F7 в конкретную панель: это создаёт два независимых состояния и затрудняет блокировку игрока.

### Тестовая панель

`scenes/ui/panels/TestPanel.tscn` — минимальный пример независимого окна. Он зарегистрирован через `GameUI.tscn`, имеет `panel_id = "test"`, действие `open_test_panel` и режим `overlay`. В текущем Input Map ему назначена клавиша F7. Это пример проверки инфраструктуры, а не готовая игровая функция.

### Частые ошибки модульного UI

- **Панель не открывается:** проверьте, что PackedScene добавлена в `UIManager.panel_scenes`, корневой узел наследуется от `UIPanel`, а `panel_id` не пустой.
- **Дубликат ID:** две сцены имеют одинаковое `panel_id`. Измените ID в Inspector.
- **Действие не работает:** добавьте точно такое же имя в Project Settings → Input Map, как указано в `open_action`.
- **Escape не закрывает окно:** проверьте, что `UIManager.close_on_escape` включён и панель зарегистрирована.
- **Игрок остаётся заблокированным:** проверьте, что панель закрывается через `close_panel()`, а не только через `visible = false`. Сигнал `panel_closed` нужен для восстановления режима мыши.
- **Theme не применяется:** проверьте, что `MainUITheme.tres` назначен `GameUI`, а локальный `theme_override_*` не перекрывает нужное свойство.
- **Variation не находится:** имя в `theme_type_variation` должно в точности совпадать с именем вариации в Theme Editor, включая регистр букв.

### Внешний вид карточки предмета

Откройте:

```text
scenes/ui/inventory/InventoryItemCard.tscn
```

Структура карточки:

```text
InventoryItemCard (Button)
├── Background (Panel)
├── Icon (Label)
└── AmountLabel (Label)
```

Карточка создаётся динамически из этой сцены для каждого экземпляра предмета. Скрипт меняет только данные конкретного предмета:

- `Icon.text` получает `icon_symbol` из `ItemDefinition`;
- `AmountLabel.text` получает количество;
- `position` получает клетку из модели;
- `size` вычисляется по footprint предмета.

Оформление карточки можно менять в Inspector:

- стиль кнопки `normal`, `hover`, `pressed`, `focus`;
- цвет и размер `Icon`;
- цвет и размер `AmountLabel`;
- расположение дочерних подписей;
- скругления и границы `StyleBoxFlat`.

Не переименовывайте узлы `Icon` и `AmountLabel` без изменения путей в `scripts/inventory/inventory_ui.gd`: скрипт получает эти узлы по именам, чтобы установить символ и количество.

Размер карточки не нужно задавать вручную в сцене. Он вычисляется по размеру предмета и текущим настройкам сетки. Например, предмет 1×2 получает прямоугольный размер `62×129`, а после поворота 2×1 — `129×62`.

### Какие имена узлов являются частью кода

Не переименовывайте без изменения скрипта:

- `InventoryUI`;
- `Window`;
- `MainContainer/Content/InventoryGrid`;
- `InventoryGrid/Cells`;
- `InventoryGrid/ItemsLayer`;
- `Header/CloseButton`;
- `InventoryItemCard/Icon`;
- `InventoryItemCard/AmountLabel`.

Остальные визуальные узлы можно добавлять и переименовывать свободнее, если они не используются кодом напрямую. Для нового постоянного элемента добавьте узел в `InventoryUI.tscn`, настройте его через Inspector и подключите сигнал в коде только если он должен выполнять игровое действие.

### Что делает код, а что делает сцена

Сцена отвечает за:

- дерево UI;
- контейнеры и якоря;
- размеры окна и отступы;
- цвета, шрифты и StyleBox;
- статический текст;
- внешний вид одной клетки и одной карточки.

`inventory_ui.gd` отвечает за:

- открытие и закрытие;
- ввод `Tab`, `R`, ЛКМ и ПКМ;
- создание нужного количества клеток;
- создание карточек из `InventoryItemCard.tscn`;
- UID и связь с `InventoryDataModel`;
- Drag Anchor;
- проверку размещения;
- зелёную и красную подсветку.

Добавляя новый декоративный элемент, сначала создайте его в `InventoryUI.tscn`. Не добавляйте `Node.new()` для постоянных элементов в `_build_interface()`: этот метод должен создавать только динамические клетки и настраивать динамические карточки.

### Что безопасно менять

- Значения `@export` в `player.gd` можно менять через Inspector.
- Размер, стек и внешний вид предмета меняются в его `.tres`.
- Позиции стартовых объектов меняются в `scenes/world.tscn`.
- Параметры захвата меняются в Inspector у узла `PhysicsGrab`.

Не меняйте вручную `_items` в `InventoryDataModel`. Используйте его методы. Не меняйте сторонние файлы `addons/terrain_3d/` без отдельной проверки версии.

## 3. Как устроена архитектура

### Игрок

```text
Input → player.gd → velocity → move_and_slide()
					├→ спринт и выносливость
					└→ камера и эффекты
```

`player.gd` отвечает за движение и состояние игрока. Инвентарь, подбор и захват находятся в отдельных дочерних узлах игрока, хотя получают ссылки на его камеру и UI.

### Подбор предмета

```text
Камера → PhysicsRayQuery → WorldItem.interact(player)
	   → InventoryDataModel.add_item()
	   → остаток остаётся в WorldItem
	   → inventory_changed → InventoryUI
```

Луч строится из камеры в `scripts/player_interaction.gd`. Если найденный объект или его родитель имеет `interact`, он становится текущим интерактивным объектом. `WorldItem` передаёт количество в модель инвентаря. Метод `add_item` возвращает остаток, поэтому предмет не исчезает, если сетка заполнена.

### Выбрасывание

```text
ПКМ или F → создать WorldItem → добавить его в мир
		  → удалить количество из инвентаря
		  → применить импульс
```

Сначала создаётся физический объект. Если создание или добавление в сцену не удалось, предмет остаётся в инвентаре. Это защищает от потери предмета из-за ошибки `PackedScene`.

### Физический захват

```text
ЛКМ → луч на RigidBody3D группы grabbable
	→ проверка массы и freeze
	→ пружинная сила apply_force()
	→ проверка CollisionShape3D перед целью
```

Захват не телепортирует объект. Он прикладывает силу. Перед движением проверяется форма `CollisionShape3D`, поэтому крупный объект не должен целиком проходить через стену. Это всё равно требует ручной проверки в игре.

### Terrain3D

```text
world.tscn → TerrainCameraSetup → set_camera(camera)
terrain.tscn → data_directory → scenes/terrain_data/
Terrain3D layer 1/mask 3 ↔ предметы layer 2/mask 3
```

Камера назначается Terrain3D в одном месте — `scripts/terrain_camera_setup.gd`. Игрок больше не выполняет вторую настройку. Terrain3D 1.0.2 сам предоставляет физические формы регионов при `collision_mode = 3`.

## 4. Как добавить новый предмет

Ниже пример для предмета `medkit` размером 2×1.

### Шаг 1. Создайте ресурс

Создайте файл `resources/items/medkit.tres` на основе `ItemDefinition`. Для первого простого варианта можно использовать `BoxMesh`:

```ini
[gd_resource type="Resource" script_class="ItemDefinition" load_steps=3 format=3]

[ext_resource type="Script" path="res://resources/items/item_definition.gd" id="1"]

[sub_resource type="BoxMesh" id="MedkitMesh"]
size = Vector3(0.42, 0.18, 0.28)

[resource]
script = ExtResource("1")
item_id = &"medkit"
display_name = "Аптечка"
description = "Медицинский предмет."
size = Vector2i(2, 1)
max_stack_size = 1
icon_symbol = "+"
display_color = Color(0.8, 0.2, 0.2, 1)
world_mesh = SubResource("MedkitMesh")
collision_size = Vector3(0.46, 0.2, 0.32)
weight = 1.2
```

`size` — размер в клетках. `collision_size` — физический размер в мире. Эти значения независимы: размер в инвентаре не обязан совпадать с размером 3D модели.

### Шаг 2. Зарегистрируйте предмет

Откройте `scripts/item_catalog.gd` и добавьте ресурс:

```gdscript
&"medkit": preload("res://resources/items/medkit.tres"),
```

После этого `WorldItem`, UI и модель инвентаря смогут найти описание по `item_id`.

### Шаг 3. Добавьте предмет в мир

В `scenes/world.tscn` создайте экземпляр `scenes/items/world_item.tscn`. Укажите:

```text
item_id = &"medkit"
amount = 1
```

Поставьте объект выше поверхности Terrain3D, например на 1–3 метра, чтобы он успел упасть физически. `WorldItem` обновляет mesh и CollisionShape3D в редакторе благодаря `@tool`.

### Шаг 4. Проверьте предмет

1. Запустите `world.tscn`.
2. Дождитесь падения предмета.
3. Подойдите к нему и убедитесь, что появилась подсказка E.
4. Нажмите E.
5. Откройте Tab и проверьте размер карточки 2×1.
6. Перетащите карточку, затем поверните R.
7. Нажмите ПКМ по карточке и убедитесь, что предмет снова появился в мире.

## 5. Как добавить интерактивный объект

Текущая система использует простой контракт: объект должен иметь метод `interact(player)`. Дополнительно он может иметь `get_interaction_prompt()`.

Создайте, например, сцену `scenes/objects/openable_box.tscn`:

```text
Node3D
├── MeshInstance3D
├── StaticBody3D
│   └── CollisionShape3D
└── OpenableBox.gd
```

Скрипт:

```gdscript
extends Node3D

var is_open := false

func get_interaction_prompt() -> String:
	return "E — открыть ящик" if not is_open else "E — закрыть ящик"

func interact(_player: Node) -> bool:
	is_open = not is_open
	# Здесь меняется вращение крышки, проигрывается анимация и т.п.
	return true
```

Луч игрока найдёт метод у объекта или его родителя. Обычный интерактивный объект не обязан быть физическим телом.

Разница между типами объектов:

- `WorldItem` — подбираемый предмет, который переводится в инвентарь.
- обычный интерактивный объект — реагирует на E, но не попадает в инвентарь;
- `RigidBody3D` группы `grabbable` — можно перемещать физической силой;
- объект может сочетать несколько возможностей, но лучше явно разделять их методами и группами.

## 6. Как добавить физически захватываемый объект

Создайте `RigidBody3D` и добавьте:

```text
PhysicsCrate (RigidBody3D)
├── MeshInstance3D
└── CollisionShape3D
```

Настройки:

```text
collision_layer = 2
collision_mask = 3
continuous_cd = true
mass = 5.0
group = grabbable
```

Не добавляйте такой объект в группу `world_pickup`, иначе `PhysicsGrab` его пропустит. Группа `grabbable` — явный признак, что объект разрешено поднимать.

## 7. Как работать с инвентарём

Модель находится в `InventoryData` и имеет методы:

```gdscript
var rest := inventory.add_item(&"metal_scrap", 4)
var removed := inventory.remove_item(uid, 1)
var allowed := inventory.can_place(uid, Vector2i(2, 3), false)
var moved := inventory.move_item(uid, Vector2i(2, 3), true)
```

`add_item` возвращает остаток. `remove_item` возвращает фактически удалённое количество. `uid` идентифицирует экземпляр карточки, а `item_id` идентифицирует тип предмета.

Размер с поворотом вычисляется так:

```gdscript
Vector2i(definition.size.y, definition.size.x)
```

### Точка захвата при перетаскивании

Инвентарь хранит положение предмета как клетку его верхнего левого угла. Во время перетаскивания UI дополнительно хранит `_drag_anchor_cell` — клетку внутри предмета, на которую пришёлся клик.

Например, если предмет занимает 2×2 и клик пришёлся по правой нижней клетке, anchor равен `(1, 1)`. Положение карточки при движении считается так:

```text
клетка под курсором − клетка захвата = верхняя левая клетка предмета
```

Поэтому карточка не прыгает верхним левым углом к курсору. Курсор продолжает указывать на ту же клетку предмета. Координаты мыши переводятся в локальные координаты `_board` через `get_global_transform_with_canvas().affine_inverse()`, а затем округляются одной общей функцией `_pixel_to_grid_cell()`.

При повороте anchor поворачивается вместе с прямоугольником. Для поворота на 90 градусов по часовой стрелке используется формула:

```gdscript
Vector2i(old_size.y - 1 - anchor.y, anchor.x)
```

Карточка, подсветка и `InventoryDataModel` используют одну и ту же пару функций `_get_footprint()` и `_footprint_to_pixels()`. Поэтому предметы 1×2, 2×1, 1×3 и другие прямоугольники сохраняют правильный размер.

Модель сама проверяет границы и пересечения. UI только показывает результат проверки и передаёт окончательное действие в `move_item`.

## 9. Частые ошибки

### `Node not found`

Godot не нашёл узел по пути. Проверьте имена `Head/Camera3D`, `HUD/GameUI/UIManager`, `InventoryData` и структуру `player.tscn`.

### `Invalid access to property`

Скрипт получил `null` или объект другого типа. Проверьте `@onready` ссылки и наличие нужного дочернего узла.

### `Invalid call`

Метод вызван у объекта, который его не имеет. Для интерактивных объектов проверьте, что есть `interact(player)`. Для нового Terrain3D API сверяйтесь с установленной версией 1.0.2.

### Предмет проваливается

Проверьте `CollisionShape3D`, его `shape`, позицию предмета, `collision_layer = 2`, `collision_mask = 3`, `Terrain3D.collision_mode = 3` и наличие региона в `scenes/terrain_data/`.

### Предмет не помещается

Проверьте `size`, свободные клетки и `max_stack_size`. Если предмет 1×2, попробуйте R: модель теперь учитывает обе ориентации при автоматическом добавлении.

### Неизвестный `item_id`

Проверьте `scripts/item_catalog.gd` и совпадение ID в `.tres`, `world.tscn` и коде. `InventoryDataModel` выдаёт ошибку, но сохраняет неизвестную запись в модели, чтобы содержимое не исчезло молча.

### E не работает

Проверьте CollisionShape3D объекта, расстояние `interaction_distance` и наличие `interact`. Луч должен попадать в физическое тело объекта или его дочерний узел.

### Физический захват не работает

Проверьте группу `grabbable`, `freeze`, массу и collision mask. Предметы группы `world_pickup` специально не захватываются этой системой, потому что они подбираются через E.

### Ошибка UID

UID — внутренний идентификатор Godot. Не удаляйте `.uid` без причины. Если Godot пересоздал незатреканный UID, проверьте `git status` и решите, должен ли он быть добавлен в репозиторий.

## 11. Словарь терминов

- **Node** — узел. Один объект в дереве сцены.
- **Scene** — сцена. Сохранённое дерево узлов, которое можно вставить в другую сцену.
- **Resource** — ресурс с данными, например описание предмета или mesh.
- **PackedScene** — загруженная сцена, которую можно создавать через `instantiate()`.
- **Signal** — сигнал о событии. Например, `inventory_changed` сообщает UI об изменении данных.
- **Collision Layer** — слой, на котором объект виден для физических запросов.
- **Collision Mask** — слои, с которыми объект проверяет столкновения.
- **UID** — уникальный идентификатор ресурса Godot.
- **Item Definition** — общее описание типа предмета: имя, размер, mesh и масса.
- **Item Instance** — конкретный экземпляр предмета в инвентаре с UID и количеством.
- **RayCast** — луч, который ищет первое физическое пересечение.
- **Shape Cast** — проверка объёмной формы, полезна для крупных объектов.
- **Runtime** — время работы запущенной игры.
- **Editor** — редактор Godot, в котором создаются сцены и ресурсы.

Если поведение не проверялось вручную в запущенном окне, считайте его требующим ручной проверки по чек-листу выше.
